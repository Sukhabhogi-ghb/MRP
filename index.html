Hub Stability Map — Incomplete Return Rate by Hub
What the data shows: Hub 2 and Hub 5 consistently record the highest incomplete return rates in the dataset, each exceeding 15%, while Hub 1 sits closest to the documented LoT benchmark of ~14% (Jones et al., ACM Digital Library). This uneven distribution across hubs suggests that location-specific process weaknesses — such as inconsistent volunteer inspection practices — are a stronger driver of incomplete returns than item type alone. Hubs with higher rates also correspond to higher inventory mismatch flags, confirming that when items are returned incomplete, the system record diverges from physical reality (DeHoratius & Raman, 2008).
2
Item Vulnerability Matrix — Incomplete Returns by Category
What the data shows: Power Tools have the highest share of incomplete returns relative to their transaction volume, followed by Camping Gear. Kitchen Appliances and Event Equipment show lower but non-trivial rates. This aligns with Mont (2002), who notes that shared-use systems face higher operational risk when items have multiple detachable components — a characteristic most prominent in Power Tools (cords, bits, attachments) and Camping Gear (stakes, straps, accessories). The pattern suggests that item complexity, not borrower behavior alone, is a structural driver of incompleteness.
3
Delay Impact — Average Delay Minutes by Hub & Incomplete vs. Complete Returns
What the data shows: The time series reveals that incomplete returns are not uniformly distributed across the year — peaks appear during mid-year months (June–August), which typically correspond to high-demand lending periods for Camping Gear and Event Equipment. This seasonal pattern supports the need for proactive staffing and inspection protocols during peak periods rather than reactive remediation after delays occur. The Shareable Library of Things Toolkit notes that volunteer-run models are especially vulnerable during high-demand periods when operational capacity is already stretched.
4
Delay Impact — Average Delay Minutes by Hub & Incomplete vs. Complete Returns
What the data shows: Across all 5 hubs, incomplete returns generate dramatically longer delays than complete returns. The average delay for incomplete returns ranges from 38–55 minutes depending on the hub, compared to near-zero delays for complete returns. This is consistent with Möhlmann (2015), who demonstrated that service reliability directly affects user satisfaction in collaborative consumption systems. Hub 3 shows the steepest delay gap, suggesting that its reprocessing workflow is less efficient than other hubs, compounding the impact of each incomplete return.
5
Satisfaction Erosion — Avg. Satisfaction Score by Delay Bucket
What the data shows: Resident satisfaction scores drop sharply as delay minutes increase. Transactions with zero delay average a satisfaction score above 4.0, while those delayed 60+ minutes fall below 2.0. This confirms Möhlmann's (2015) finding that service availability and reliability are primary determinants of continued use in sharing platforms. The steepest decline occurs between the 0–30 minute and 30–60 minute brackets, meaning even moderate delays — triggered by a single missing component — meaningfully erode trust in the BorrowBox service.
6
Inventory Accuracy — Match vs. Mismatch by Hub
What the data shows: Inventory mismatches — where the system record says "available" but the physical item is incomplete — are concentrated in Hubs 2, 3, and 5. The overall mismatch rate in the dataset is approximately 12%, consistent with the 5–20% range documented by DeHoratius & Raman (2008) in their empirical study of inventory record inaccuracy. These mismatches represent the core operational problem: items appear ready in the system but fail at the point of pickup, directly causing the service disruptions that motivated this research project.

Logging Behavior — Incomplete Rate by Data Entry Mode
What the data shows: Transactions logged via the App show a lower incomplete return rate compared to Manual entry, with Checklist-based entries falling in between. This pattern supports Rathod's (2024) argument for standardized, technology-enabled inventory management: when staff use structured digital tools, inspection completeness improves. Manual logging — associated with the highest incomplete return rate — also corresponds to greater data fragmentation, consistent with the technology involvement findings in the problem definition phase of this project.

What the data shows: Incomplete returns trigger a compounding operational cascade. Each incomplete return that is not caught at time of return requires reprocessing by a volunteer, risks cancellation of the next reservation, and generates replacement costs averaging over $190 per incident. The proportion of low satisfaction scores (1–2 out of 5) among affected residents directly quantifies the resident trust erosion described in the problem statement. As BorrowBox scales, this cascade effect will amplify without a systematic visibility solution — the core justification for this analytics platform.

What Changed After the Solution Was Implemented

The BorrowBox data analysis revealed a 14 percent incomplete return rate, 12 percent inventory mismatch rate, delays averaging 38 to 55 minutes, and satisfaction scores collapsing below 2.0 after 60-minute delays. Four solution features were built to address these failures: a mandatory Return Inspection Checklist at the point of return, an automated Alert and Flag System for hub managers, a Hub Manager Action Panel for daily task management, and a Resident Compliance View targeting repeat offenders.

The charts below show the simulated future state after those four features are in operation. Dataset 2 applies the same 22 variables and 2,500 transactions but reflects the improvement benchmarks the literature suggests are achievable with structured digital inspection tools. The before figures are from Dataset 1. The after figures represent Dataset 2.
